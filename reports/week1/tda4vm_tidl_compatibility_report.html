0. 핵심 결론 요약

edgeai-tidl-tools 11_00_06_00 tag의 문서·예제 코드를 기준으로, SK-TDA4VM(am68pa)에서 영상·IMU 융합 모델을 TIDL로 가속할 때 결정해야 할 사항과 미리 차단해야 할 Risk를 정리했다.

Runtime 선택 — ONNX Runtime 경로 권장. TIDL은 OSRT(Open Source Runtime) 3종(ONNX Runtime, TFLite Runtime, TVM/Neo-AI DLR(Deep Learning Runtime))과 그 하위 계층인 TIDL-RT(C API)를 제공한다. Operator(연산자) 매핑 표와 공식 예제가 갖춰진 경로는 ONNX Runtime과 TFLite Runtime 2가지다. 과제 모델은 PyTorch 학습·2-input 구조이고, TI Model Zoo 검출 모델과 Transformer 지원이 ONNX 중심이므로 ONNX Runtime + TIDL Execution Provider를 기본 경로로 둔다.
→ PyTorch → ONNX(opset ≤ 19, 고정 shape) → onnxruntime_tidl 1.15.0
TDA4VM 전용 Quantization 제약. TDA4VM(AM68PA)은 Symmetric(대칭) PTQ(Post-Training Quantization, 학습 후 양자화) 8/16-bit와 Mixed Precision(혼합 정밀도), ONNX QDQ(Quantize-Dequantize) 모델, QAT(Quantization Aware Training, 양자화 인지 학습)를 지원한다. 반면 Asymmetric(비대칭)·Per-channel 양자화(quantization_scale_type=4)와 TFLite INT8 모델 직접 import(=3)는 지원하지 않는다.
→ 다른 SoC(AM62A/AM68A/AM69A) 예제의 양자화 설정을 그대로 복사하지 않는다.
IMU 분기의 LSTM/GRU는 가속 불가. LSTM·GRU·RNN은 11_00_06_00 지원 Operator 목록에 없어 Cortex-A72(ARM)에서 실행된다. 이 Operator들은 11_02_16_00부터 목록에 추가되었으나, 이를 포함한 tools(11_02_16/17/20/21_00) 중 SDK 11.00에 적용 가능한 패치는 J784S4 ADAS SDK 전용뿐이다. 즉 TDA4VM + SDK 11.00 조합에서는 사용할 수 없고, 최소 SDK 11.01 + 11_02_17_00이 필요하다.
→ IMU 시계열 분기는 Conv(1×k)·Gemm(완전연결) 기반으로 설계한다.
Batch는 1로 고정해 배포. TDA4VM은 C7x DSP(Digital Signal Processor)+MMA(Matrix Multiply Accelerator)가 1개이므로 multi-core Batch 모드(inference_mode 1/2)가 해당되지 않는다. 단일 DSP의 Batch 내부 최적화는 “매우 작은 해상도”에서만 적용되고, Slice는 batch=1만, Concat은 batch 축 불가, Add/Mul broadcasting은 batch 축 제외 등 Operator 제약이 있다.
→ 시간 축은 Batch가 아니라 W(width) 또는 C(channel) 축에 배치한다.
검출(신호 인식) 후보는 TI Model Zoo의 YOLOX-lite. edgeai-modelzoo r11.0의 YOLOX-nano/tiny/s-lite는 TIDL 후처리 가속(meta_arch_type=6)과 prototxt가 제공된다. 이름에 gplv3가 붙은 YOLOv5/v6/v7/v8 변형은 shortlist에서 제외되어 있고, 라이선스 의무 검토가 필요하다.
버전 고정이 최우선 Risk 관리 항목. GitHub master(현재 11_02_20_00) 문서는 11_00_06_00과 지원 기능이 다르다. Tools(컴파일 도구)와 보드 Firmware 버전이 다르면 Artifact(컴파일 산출물)가 실행되지 않는다.
→ 판단 근거는 tag 문서만 사용하고, compile 설정·버전을 실험 기록에 함께 남긴다.

2. [Topic 2] TIDL Runtime·Framework·Quantization 지원 모델

2.1 TIDL 동작 구조

TIDL은 학습이 끝난 모델 파일(.onnx, .tflite)을 x86 PC에서 Compile(분석·양자화·메모리 계획)하여 Artifact를 만들고, 보드에서는 OSRT가 이 Artifact를 읽어 지원되는 부분을 C7x DSP + MMA로 Offload(가속기 할당)한다. 지원되지 않는 Operator는 같은 OSRT가 Cortex-A72에서 실행한다(Heterogeneous Execution, 이종 실행). 지원 Operator가 연속된 구간 하나가 Subgraph(부분 그래프) 하나가 된다.

  • Compile은 x86에서만 가능하다. 보드는 Inference(추론)만 수행한다(README.md 지원 기능 표).
  • Host Emulation은 C7x 동작을 PC에서 재현하는 기능 확인 단계다. Layer별 실행 cycle은 보드에서 debug_level=1일 때만 출력된다(docs/tidl_osr_debug.md).
  • Compile 결과로 tempDir/runtimes_visualization.svg가 생성되며, 어떤 노드가 C7x로, 어떤 노드가 ARM으로 배정되었는지 확인할 수 있다.

Code Customizing이 필요한 경우

  • 미지원 Operator 대체: osrt-model-tools/.../tidl_onnx_model_optimizer의 변환 규칙(예: convert_resize_params_size_to_scale, convert_maxpool_to_cascaded_maxpool, convert_softmax_axis_*, convert_gemm_to_matmul_and_add, expand_layernorm_to_component_ops) 또는 onnx-graphsurgeon으로 Graph(계산 그래프) 수정.
  • Offload 범위 조정: deny_list:layer_type, deny_list:layer_name, allow_list:layer_name(실험적)로 특정 Operator를 ARM/C7x에 강제 배정.
  • 다중 입력·비영상 입력 추론 코드: 저장소 예제(onnxrt_ep.py, tflrt_delegate.py)는 분류·검출·분할의 단일 이미지 입력을 전제로 한다. 영상+IMU 2-input 모델은 docs/custom_model_evaluation.md의 “Custom Model Evaluation” 절차로 별도 추론 스크립트를 작성해야 한다.
  • 전처리·후처리: 입력 정규화(mean/scale)·layout 변환을 모델 안에 넣거나(add_data_convert_ops, 실험적) 애플리케이션에서 구현. 검출 후처리는 Meta Architecture(prototxt)로 TIDL에서 처리하거나 ARM에서 구현.

3.6 호환성 검증 절차

docs/tidl_osr_debug.md의 권장 순서를 과제 모델에 맞게 정리했다. 각 단계 결과는 실험 기록(모델 버전, compile option, calibration 데이터 목록, tools tag, SOC, ORT optimization level)과 함께 보관한다.

  1. ARM-only 기준 결과 확보 — TIDL 없이 CPUExecutionProvider(예제는 -d 옵션)로 추론해 기능상 정답 출력을 만든다.
  2. Compile 및 Offload 확인 — debug_level=1~2로 compile 후 Parsing 요약, tempDir/runtimes_visualization.svg, Subgraph별 *_tidl_net.bin.svg로 ARM 배정 노드와 원인(마우스 hover 정보)을 확인한다.
  3. 32-bit 비교 (PC) — tensor_bits=32로 Host Emulation하여 1번 결과와 같으면 graph 변환은 정상이다(양자화 영향 배제).
  4. 8-bit PTQ — accuracy_level=1, calibration_frames 20~50으로 compile 후 정확도를 비교한다.
  5. 16-bit · Mixed Precision — 8-bit 정확도가 부족하면 16-bit로 상한을 확인하고, 수동(output_feature_16bit_names_list) 또는 자동(mixed_precision_factor)으로 조정한다. Layer별 오차는 debug_level=4 trace로 비교한다.
  6. 보드 성능 측정 — SK-TDA4VM에서 debug_level=1로 layer cycle을 받아 병목 Layer를 찾는다(C7x 1 GHz 기준 cycle ÷ 106 = ms).
  7. PC–보드 일치 확인 — 양쪽에서 debug_level=3 fixed-point trace(/tmp)를 생성해 비교한다. 첫 불일치 Layer가 보고 대상이다(*.layer_info.txt로 dataId ↔ Layer 이름 대응).

4. 결론 및 다음 작업

4.1 결론

  • Runtime·Framework: PyTorch 학습 → ONNX(opset ≤ 19, 고정 shape, batch=1) → ONNX Runtime + TIDL EP를 기본 경로로 한다. TensorFlow를 쓰는 경우 float TFLite → TFLite Runtime 경로를 쓰되 INT8 TFLite import는 TDA4VM에서 쓸 수 없다.
  • Quantization: Symmetric PTQ 8-bit를 기본으로 하고, 회귀 출력은 16-bit·Mixed Precision으로 보완한다. 정확도 목표 미달 시 TDA4VM 대상 QAT를 검토한다.
  • 모델 구조: 영상 분기는 TI Model Zoo lite 구조, 신호 인식은 YOLOX-lite 계열, IMU 분기는 LSTM/GRU 대신 Conv(1×k)·Gemm, Fusion은 channel 축 Concat으로 구성하면 11_00_06_00 지원 Operator 안에서 전체 Offload를 목표로 할 수 있다.
  • Batch: TDA4VM에서는 batch=1 배포가 기준이며, 시간·센서 정보는 batch가 아닌 W/C 축으로 표현한다.
  • 버전: Tools·Firmware·SoC·OSRT 버전을 한 묶음으로 기록·고정하는 것이 가장 큰 오류 원인을 제거한다.
